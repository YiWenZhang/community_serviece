# 多社区权限接口变更 1.2.0

所有接口继续使用Cookie Session和CSRF。当前业务社区使用请求头 `X-Community-Id`，必须是管理员/统计员可访问的社区，或者当前网格员已被分配且启用的社区；服务器每次重新核验，不信任前端缓存。没有请求头时选择账号默认社区，默认社区已被撤销则选择仍获授权的第一个社区。网格员无授权社区时不能操作业务。

| 方法 | 路径 | 功能及权限 |
| --- | --- | --- |
| GET | `/api/v1/communities` | 返回当前角色允许访问的社区元数据；管理员与统计员全部，网格员仅已分配且启用的社区 |
| POST | `/api/v1/communities` | 管理员创建社区，同时建立默认网格 |
| PUT | `/api/v1/communities/{id}` | 管理员修改代码、名称、介绍、状态，需version |
| POST | `/api/v1/communities/{id}/icon` | 管理员上传PNG/JPEG，multipart字段file，最大2MB、400万像素；重新编码为最大256像素PNG |
| GET | `/api/v1/communities/{id}/icon` | 对有权访问该社区的已登录账号返回PNG，不返回原图 |
| GET | `/api/v1/communities/{id}/workers` | 管理员查询已分配该社区的有效网格员 |
| GET | `/api/v1/communities/{id}/grids` | 管理员查询目标社区的启用网格 |
| GET | `/api/v1/users` | 管理员查询全部账号，增加communityIds |
| POST/PATCH | `/api/v1/users`、`/api/v1/users/{id}` | 增加communityIds数组，网格员至少一个社区；修改后账号旧会话失效 |
| POST | `/api/v1/elders` | 增加可选ownerUserId，管理员需指定该社区的有效网格员；网格员只能归自己负责 |
| POST | `/api/v1/elders/{id}/transfer` | 增加可选communityId作为目标社区；保留gridId、ownerUserId、reason、version |
| GET | `/api/v1/reports/metrics` | 增加可选communityId；管理员/统计员不传即汇总全部社区，网格员仍为当前社区本人范围 |
| POST | `/api/v1/report-jobs` | query增加communityId，仍需Idempotency-Key；后台恢复排队社区并重新鉴权 |
| GET | `/api/v1/report-jobs` | 分页查看报表，管理员/统计员可查看全部，网格员只能查看本人申请的当前社区报表 |
| GET | `/api/v1/audit-logs` | 管理员查询全部社区日志，可按communityId、actor（账号模糊匹配）、action（精确代码）、result筛选 |

社区写接口字段为code、name、description、status（ACTIVE/INACTIVE）、version。用户的sys_user.community_id仍保留为默认值，实际授权以user_community为准，不要求一个账号复制成多个账号。

统计员的权限在Actor层限制为report相关能力，即使错误授予老人或系统维护权限也不能执行；不能同时把统计员和其他岗位角色分配给同一账号。管理员有跨社区管理能力，业务页面通过顶部社区选择器逐个处理；不会因为切换社区而向网格员开放别人的老人。

跨社区移交前需要结束未闭环通知与跟进；同社区移交维持原有同步转交逻辑。已结束通知保留原社区，以保持历史报表统计口径；跨社区移交后老人继续沿用原编号。

操作日志保留原业务事件，并增加HTTP_GET/POST/PUT/PATCH/DELETE事件。HTTP事件包含method、path、status和traceId，不保存请求体、密码、密钥或原始查询字符串。失败或拒绝请求也记录，匿名拒绝由安全日志记录。
