# 社区老年服务系统数据库使用说明

**1.2.0升级提示：已有库请先备份并按[多社区权限升级说明](../多社区权限升级说明.md)执行V002，不要重导初始化库。V002增加4张多社区相关表，AI模块增加6张表，完整系统共41张表。下文为最初31张业务表的导入说明，历史表数量与权限描述以新版说明为准。**

日期：2026年10月16日。

本目录提供可直接导入的MySQL数据库脚本。数据库名为`community_elder_service`，包含设计文档中的31张非AI表，排除了政策文档、政策版本、政策片段、问答会话、问答消息和问答引用六张表。本说明仅介绍数据库；后端和前端的启动方式见仓库根目录README。

## 三 如何启动和停止MySQL

MySQL是独立的数据库服务，DBeaver是连接它的客户端。打开DBeaver不会自动启动MySQL。

在PowerShell检查服务：

```powershell
Get-Service MySQL80
```

Status为Running表示已经启动。若为Stopped，以管理员身份打开PowerShell后执行：

```powershell
Start-Service MySQL80
```

需要停止时，以管理员身份执行：

```powershell
Stop-Service MySQL80
```

也可按Win和R，输入`services.msc`，找到`MySQL80`，右键选择“启动”。如果希望开机自动启动，在该服务“属性”中将启动类型设为“自动”。已经运行时无需再直接运行mysqld.exe，以免启动第二个实例或产生端口冲突。Windows服务的启动方式参见[MySQL官方说明](https://dev.mysql.com/doc/refman/8.0/en/windows-start-service.html)。

## 四 首次导入数据库

### 方法一 使用本机导入脚本

在PowerShell执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "D:\Desktop\CummityService\database\本机导入.ps1"
```

窗口出现`Enter password:`后，输入你现有MySQL的root密码并回车；密码不回显。脚本不重置密码、不创建数据库账号，密码不写入文件、环境变量、命令参数或聊天。`ExecutionPolicy Bypass`仅对这次PowerShell进程生效。

如果使用其他已有建库账号：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "D:\Desktop\CummityService\database\本机导入.ps1" -MySqlUser "你的账号"
```

导入账号需具备该项目数据库的创建、建表、外键及插入权限。结束时窗口应显示数据库名、服务器版本、表数量31及导入摘要，并提示“导入成功”。`local-import-status.json`的status为SUCCESS才说明实际目标实例的导入命令成功；WAITING_FOR_PASSWORD表示仍在等待输入，FAILED表示没有完成。

### 方法二 MySQL命令行

先运行：

```powershell
& "D:\Desktop\install\bin\mysql.exe" --no-defaults --protocol=TCP -h 127.0.0.1 -P 3306 -u root -p --default-character-set=utf8mb4
```

输入现有密码，进入`mysql>`后执行下面的MySQL客户端命令。此处路径使用正斜线，末尾不加多余中文标点：

```sql
source D:/Desktop/CummityService/database/导入数据库.sql
```

必须是首次导入。命令行`source`的错误处理行为与整批标准输入方式不同；若出现任何错误，立即停止并检查，不要把随后看到的表数量当作已经完整导入的证明。优先采用方法一，其批处理遇到错误会停止并返回失败。

### 方法三 DBeaver执行SQL脚本

按下一节先创建MySQL服务器连接，数据库栏在首次导入前可以留空。通过“SQL编辑器”打开`导入数据库.sql`，确认连接是本机3306。

使用“执行SQL脚本”，不要只执行光标所在的一条语句。很多版本快捷键为Alt和X，最终以菜单显示为准。若弹出错误处理设置，选择遇错停止，不选择忽略全部错误。执行完后刷新连接，查看新数据库。不要同时用三种方法重复初始化。

## 五 在DBeaver查看数据库

1. 打开DBeaver，选择“数据库”→“新建数据库连接”。
2. 选择“MySQL”驱动，进入下一步。
3. 按下面的参数填写连接。如果数据库还未导入，数据库栏先留空；导入后填入项目数据库名。

| DBeaver字段 | 填写值 |
| --- | --- |
| Host 主机 | 127.0.0.1 |
| Port 端口 | 3306 |
| Database 数据库 | community_elder_service |
| Username 用户名 | root，或你已有的MySQL账号 |
| Password 密码 | 该MySQL账号现有密码 |
| 连接名称 | 本机社区老年服务数据库 |

4. 点击“测试连接”。首次使用可能要求下载MySQL驱动，按照DBeaver提示下载。
5. 测试成功后点击“完成”。在数据库导航器中展开连接→数据库或Schemas→`community_elder_service`→Tables。
6. 若刚导入没有显示，右键连接选择“刷新”，必要时“编辑连接”把数据库名改为`community_elder_service`后重连。
7. 右键`elder_profile`→“查看数据”→“所有行”，可看到三条虚构档案。双击表可查看列、外键、索引及中文注释。
8. 打开`verify_database.sql`，在该连接下执行整个脚本，可看到通知闭环、跟进任务及两个50%的示例比例。
9. 右键数据库选择“查看图表”或创建ER图，可查看外键关联；不同DBeaver版本菜单名称略有差异。

MySQL账号和`sys_user`里的应用账号是两套账号。`admin_demo`、`grid_demo`、`stats_demo`是初始化时禁用的应用样例账号，不能用于DBeaver连接。DBeaver连接流程参见[官方连接文档](https://dbeaver.com/docs/dbeaver/Create-Connection/)。

## 六 样例数据怎么看

业务样例只有一个社区、一个网格、三条虚构老人档案、两个通知批次、两条接收对象、三次触达、两条跟进任务及一条满意度反馈。另有角色、权限及服务需求等初始化字典，所以总行数多于业务样例条数。

| 数据 | 示例含义 |
| --- | --- |
| elder_profile id1 | SH-L-2026-001，1948年10月，男，生日关怀与接种提醒需求 |
| elder_profile id2 | SH-L-2026-002，1955年11月，女，接种提醒需求 |
| elder_profile id3 | SH-L-2026-003，1960年3月，女，健康讲座需求 |
| 通知NT-202610-001 | 家属首次未确认转告，跟进后明确确认，通知闭环 |
| 通知NT-202610-002 | 上门无人，保留未联系状态和待跟进任务 |
| 疫苗状态 | 1人符合资格且完成、1人符合资格尚未接种、1人资格未知 |
| 通知覆盖率 | 1除以2为50%，多次触达不重复计人数 |
| 该周期接种率 | 已完成且符合资格1人除以符合资格2人为50% |

所有示例日期固定为2026年10月；时间字段为UTC，上海时间为其加8小时。导入日期变化不会改写业务发生日期，所以待办可能已经逾期，这是样例设定。

按照设计文档，老人编号保存真实AES-256-GCM密文，DBeaver中看到十六进制或BLOB显示是正常的，不是乱码。密文布局为12字节nonce后接密文和16字节认证标签；HMAC使用独立密钥。`演示数据密钥.json`仅供开发验证，正式环境必须换用受控密钥，禁止继续使用演示密钥。这里没有存储老人姓名、身份证号、手机号或家庭地址。

文件、附件关联、报表作业、指标快照、持久队列和outbox表暂时留空。没有真实文件、短信平台或后端任务时，不伪造“已上传签字”“短信已发送”“报表已生成”或待执行的外部副作用。

## 七 约束与设计落实范围

脚本包含31张表、每列中文注释、主键、业务唯一索引、常用查询索引、物理外键及核心枚举CHECK。档案的网格和负责人、通知接收对象、跟进任务等关键关系通过复合外键校验社区一致性。默认外键限制删除，无级联删除。

以下规则仍需后端事务和权限实现，不能只用建表脚本保证：当前用户只能操作本人档案、历史表只追加、每次状态转移是否合法、上门确认至少一个合格签字附件、同一对象反馈版本的串行递增、接种当前状态与核验事实同步、规则参数白名单和审计账号权限。`version`字段由应用在写入时校验和递增，不会由MySQL自动提供乐观锁。

## 八 常见问题

**连接拒绝或Connection refused**：先运行`Get-Service MySQL80`，确认Running。检查主机127.0.0.1、端口3306，避免误连独立验证使用的13316；验证实例已在测试结束后关闭。

**Access denied或1045**：账号、密码或账号允许的来源不匹配。使用现有有效MySQL账号，不要把应用用户当成数据库用户。本脚本不会修改或找回root密码。

**数据库已存在或1007**：说明名称已被占用或已经导入。先查看31张表和样例是否齐全；不要删除已有数据。想要重建时应先备份，再单独制定重建脚本。

**DBeaver看不到库**：刷新或重新连接，确认选择正确实例和数据库；同时确认连接账号有该库权限。可在SQL编辑器执行：

```sql
SHOW DATABASES LIKE 'community_elder_service';
USE community_elder_service;
SHOW TABLES;
SELECT COUNT(*) FROM elder_profile;
```

**中文乱码**：脚本编码选择UTF-8，连接字符集使用utf8mb4。老人编号密文本来就是二进制，不能通过改字符集变成明文。

**服务无法启动**：查看现有服务配置`D:\Desktop\mysql\my.ini`引用的错误日志及端口占用。不要执行`mysqld --initialize`操作现有数据目录，初始化不是启动服务。
